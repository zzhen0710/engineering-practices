# Engineering Practices

一个从真实项目实践中持续提炼的个人工程积累仓库。

这个仓库用于长期沉淀可复用的工程经验、配置、组件与项目模板。目标不是尽可能收集大量现成模板，而是在实际开发过程中，逐渐识别那些真正反复出现、值得复用的工程经验，并将其抽象、整理和维护下来。

## 核心原则

> 不在缺乏实践之前提前抽象。

一个工程经验通常应经历这样的过程：

```
第一次遇到真实问题
        ↓
在项目中解决
        ↓
后续再次遇到类似问题
        ↓
比较不同实现
        ↓
识别稳定的共同部分
        ↓
抽象并沉淀
        ↓
在新项目中复用
        ↓
根据新的实践继续改进
```

仓库应该随着真实工程能力自然成长，而不是为了让内容看起来丰富而提前填充大量未经实践验证的模板。

## 仓库结构

### [Snippets](app://-/snippets/)

小型、相对独立、可直接复用的工程配置、规范或知识片段。

可能包括 Git、CMake、编译器、调试、代码格式、开发环境等方面的工程实践。

### [Components](app://-/components/)

从真实项目中逐渐抽象出的可复用工程组件。

只有当某类功能的职责、接口和行为已经相对稳定，并且具有明确复用价值时，才适合沉淀为组件。

### [Templates](app://-/templates/)

经过实际项目验证，可以直接作为新项目起点使用的完整工程骨架。

模板是仓库中抽象层级最高的内容，不应仅因为“未来可能有用”而提前创建。
