# Engineering Practices

个人工程学习记录与工程范式积累仓库。

用于长期记录真实开发中的学习、实验与问题分析，并从实践中逐渐提炼可复用的工程配置、开发规范、组件和项目模板。

> 学习过程可以及时记录，工程范式应经过实践检验后再提炼。

## 核心原则

> 不在缺乏实践之前提前抽象。

一个工程经验通常应经历这样的过程：

```
第一次遇到真实问题
        ↓
在项目中解决
        ↓
后续再次遇到类似问题
        ↓
比较不同实现
        ↓
识别稳定的共同部分
        ↓
抽象并沉淀
        ↓
在新项目中复用
        ↓
根据新的实践继续改进
```

仓库应该随着真实工程能力自然成长，而不是为了让内容看起来丰富而提前填充大量未经实践验证的模板。

## 仓库结构

### [Notes](notes/README.md)

Linux / C++ 工程学习笔记、实验记录、问题分析与调试经验。

保留真实学习过程，为后续提炼工程范式提供基础。

### [Snippets](snippets/README.md)

小型、相对独立、可直接复用的工程配置、规范或知识片段。

可能包括 Git、CMake、编译器、调试、代码格式、开发环境等方面的工程实践。

### [Components](components/README.md)

从真实项目中逐渐抽象出的可复用工程组件。

只有当某类功能的职责、接口和行为已经相对稳定，并且具有明确复用价值时，才适合沉淀为组件。

### [Templates](templates/README.md)

经过实际项目验证，可以直接作为新项目起点使用的完整工程骨架。

模板是仓库中抽象层级最高的内容，不应仅因为“未来可能有用”而提前创建。
