# Engineering Practices

从真实项目中提炼可复用 C++ / Linux 工程经验的仓库。

用于长期记录真实开发中的学习、实验与问题分析，并从实践中逐渐提炼可复用的工程配置、开发规范、组件和项目模板。

> 学习过程可以及时记录，工程范式应经过实践检验后再提炼。

当前规则见 [AGENTS](AGENTS.md)。2026-10-18 核对：已有 Ubuntu 开发环境实录和 C++ 命名规范，尚无组件或完整模板实现；历史实录不等于本次重做成功。

本仓保存可迁移的工程认识和复用材料。项目专属的实现过程、开发状态、完整故障证据留在原项目；此处解释可复用部分，并链接来源及适用条件。AI 如何选上下文、审查和验证的可迁移方法放在 ai-coding-notes，个人状态由本地 personal-hub 维护。没有新的复用结论时，不为每次项目任务新增笔记。

## 核心原则

> 不在缺乏实践之前提前抽象。

一个工程经验通常应经历这样的过程：

```
第一次遇到真实问题
        ↓
在项目中解决
        ↓
后续再次遇到类似问题
        ↓
比较不同实现
        ↓
识别稳定的共同部分
        ↓
抽象并沉淀
        ↓
在新项目中复用
        ↓
根据新的实践继续改进
```

仓库应该随着真实工程能力自然成长，而不是为了让内容看起来丰富而提前填充大量未经实践验证的模板。

## 结构与入口

| --- | --- | --- |

| [Templates](templates/README.md) | 完整工程骨架经过实际使用后收录 | 仅有说明页，暂无实现 |

根 README 只保留模块入口，具体条目由各目录索引维护，不重复维护完整条目清单。Components/Templates 的说明页保留，不构成现在必须填充的任务。

当前不另建 cpp、linux、network、testing 等分类。新增少量文章先进入既有目录；同主题尽量集中，内容明显膨胀或主题独立、现有结构不便查阅时再细分。先有实际内容再建目录，不为目录完整制造笔记或空索引。

同仓使用相对链接；跨仓事实证据优先链接固定提交中的具体文件、测试或复盘，并注明实际验证版本。首页仅作导航；未提交结果标明工作区状态，不伪造提交链接。公开内容不依赖私人路径或被忽略材料，不强制双向维护链接。

本地被忽略的 GUIDE.md 是历史维护资料，保留原样；现行局部规则仍以 AGENTS 为准。
